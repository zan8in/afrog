## Three capabilities

| Capability | Location | Purpose |
| --- | --- | --- |
| Finding verdict | Every ledger row, the **Vulnerabilities** tab on a task detail | Judge, one by one, whether a finding is a real vulnerability |
| Report executive summary | Top right of the **Vulnerabilities Report** page | Generate a summary you can paste straight into a deliverable report |
| Scan parameter recommendation | On the **Scan** page after pasting targets | Recommend a set of scan parameters based on the target profile |

All three follow the same principle: **they never run automatically — a request is made only when you click**, and re-opening the same scope is served from the local cache without using up quota again.

## Finding verdict

Opening **Verdict** streams six sections word by word:

- **Conclusion**: whether this is a real vulnerability, with a confidence level (high/medium/low)
- **Basis for the judgment**: each point mapped to evidence, indicating which request or response supports the conclusion
- **Possible false positives**: the concrete false-positive scenarios
- **Manual verification**: confirmation steps you can follow in three moves or fewer
- **Impact and effect** and **Remediation**

Design constraints:

- **Infer only from evidence**: the prompt requires "do not introduce facts that are not in the evidence, say so plainly when evidence is insufficient, and strictly refrain from inventing CVEs or vendor advisories"
- **It never decides for you**: the ledger status is still changed by you manually; AI output is never automatically written as "confirmed"
- **Masked before sending**: sensitive headers such as `Cookie`, `Authorization`, `Set-Cookie` are hidden, and overly long requests/responses are truncated; but the request and response of this finding are still sent to the model service you configured.

## Report executive summary

**AI summary** at the top right of the **Reports** page produces an executive summary you can **paste straight into a deliverable report**:

- When a task is in scope (arriving from a task detail page or a schedule's "view last result"), the summary covers this scan: what scope was scanned, the overall risk rating, key risks, and recommended actions
- Without a task it rolls up across tasks under the current filter, and the summary explicitly writes "current filter result" rather than "this scan"
- The output can be copied to Markdown in one click.

A summary sends only the **statistics and the finding list** to the model (no raw request/response), so it is good at the big picture and prioritisation; when you need to judge whether a specific finding is real, use **Verdict**.

## Scan parameter recommendation

After pasting targets on the **Scan** page, click **AI recommended parameters**; the AI returns two to four reasons and packages concurrency, rate, timeout, smart concurrency, port scan, web fingerprint, severity and so on into a configuration you can adopt directly.

- **Only a target profile is uploaded**: target count, type mix, and at most 20 samples
- **Values stay within bounds**: out-of-range numbers are clamped back to the allowed range and invalid severities dropped
- **Only recommended fields are applied**: fields the model did not return keep your current setting.

## Quota and connecting

- When no model is configured the button stays visible; opening it guides you straight to **Settings → AI assist**
- The free tier allows 20 calls per month; Curated members are unlimited
- For how to connect see the AI assist section of [Settings](./10-settings.md), or the `ai` field of the [configuration file reference](../user-guide/05-configuration.md). Saving never calls the model; once filled in you can click **Test connection** on the same page to send one tiny request and confirm it works.
