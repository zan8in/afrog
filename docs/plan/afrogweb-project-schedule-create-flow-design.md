## 1. 现状与量化诊断

### 1.1 两个入口的当前结构

均为**单页抽屉、一屏到底**（无分步）。

| 入口 | 抽屉宽度 | 结构（自上而下） |
|---|---|---|
| 新建/编辑项目 | `sm:max-w-lg`（512px） | 项目名称 → 描述 → 目标（+行数/导入/校验态） → **默认参数（5 分组）** |
| 新建/编辑计划 | `sm:max-w-lg`（512px） | 计划名称 → 启用 → 执行节奏（频率+联动时间） → 扫描目标（来源/项目/文本） → 所属实例 → **扫描参数（5 分组）** |

「默认参数 / 扫描参数」区由共享组件 `ScanParamsForm` 渲染，数据来自 `SCAN_PARAM_FIELDS`。

### 1.2 量化

`SCAN_PARAM_FIELDS` 共 **31 项**；其中标记 `advanced: true` 的仅 **5 项**（爆破请求上限、响应体上限、OOB 轮询间隔/命中保留/收尾等待）。

| 指标 | 新建/编辑项目 | 新建/编辑计划 |
|---|---|---|
| 核心信息字段数 | 3（名称、描述、目标） | ≈ 7（名称、启用、频率、时间、目标来源、目标、实例） |
| 扫描参数字段数 | 31 | 31 |
| **参数占比** | **≈ 91%** | **≈ 82%** |
| 默认展开时首屏可见控件数 | ≈ 33 | ≈ 32 |
| 必填项 | 1（名称） | 2（名称、频率）+ 目标来源 | 

> 注：含条件显示项，按默认展开态统计。**用户感知的「60%」实际是 82%–91%**，问题比反馈更严重。

### 1.3 问题清单

| # | 问题 | 影响 |
|---|---|---|
| P1 | 参数区占比 82%–91%，核心信息被淹没在下方 | 新手在第一屏看不到"我到底要填什么"，先被 30 个陌生名词劝退 |
| P2 | 必填项与可选项无视觉区分 | 用户以为参数也必须逐项确认，产生"填不完"的挫败感 |
| P3 | 「用默认参数即可」这一事实从未被明说 | 项目抽屉的说明是"与默认一致的项不会被保存"，但没告诉用户**可以直接不填** |
| P4 | 参数分层只有一层（进阶折叠 5 项） | 26 项平铺，"高频"与"一生改一次"的项权重相同 |
| P5 | 计划抽屉 6 个区块平铺，无进度感 | 不知道还有多少、当前在哪一步 |
| P6 | 抽屉 512px 内塞入 30+ 控件 | 滚动很长、分组标题与字段标签层级接近，扫读困难 |

## 2. 目标与设计原则

**核心目标**：新手 60 秒内完成一次创建；老手零额外点击完成参数自定义。

| 原则 | 含义 |
|---|---|
| G1 核心先行 | 名称/目标/节奏是第一等公民，参数是"可选补充" |
| G2 默认可信 | 参数默认值直接可用；界面要**明说**"不填即为推荐值" |
| G3 快慢分流 | 新手走两步引导；老手可**一步直达**，不被强制分步 |
| G4 渐进披露 | 首屏只放高频项，其余按需展开，层级要能被"一眼看懂" |
| G5 零信息丢失 | 所有 31 项仍可访问，只是默认收起 |

## 3. 任务 1：流程优先级重排

### 3.1 重新定义"核心"与"补充"

| 层级 | 内容 | 说明 |
|---|---|---|
| **核心（必填/必选）** | 项目：名称、目标<br>计划：名称、频率、目标来源 | 缺任一项都无法创建，是"创建"这个动作的本质 |
| **次要（可选补充）** | 扫描参数（31 项）、项目描述、计划启用、所属实例 | 全都有合理默认值，不改也能跑 |

### 3.2 视觉与结构的权重映射

- 核心区：占抽屉上部，**无折叠、无分组标题**，控件直接暴露。
- 补充区：整块收起为一张"参数摘要卡"（见 §4.3），点击才展开。
- 主按钮文案从「保存」改为**语义化命名**：「创建项目」「创建计划」，并在按钮上方/下方给一句"可直接创建，参数已按推荐配置"。

## 4. 任务 2：两步式引导

### 4.1 步骤定义

```
┌ 新建计划 ────────────────────────────────┐
│ ● ① 基本信息          ② 扫描参数（可选）  │  ← 步骤条：可点击跳转
│─────────────────────────────────────────│
│ 计划名称   [___________________]         │
│ 执行频率   [每天 ▾]   时间 [09:00]        │
│ 扫描目标   [项目 ▾]   [客户A 外网 ▾]      │
│                                         │
│  高级选项 ▸ 所属实例：本机                │  ← 低频项也收起
│─────────────────────────────────────────│
│ ☑ 使用推荐扫描参数（无需调整）            │  ← 默认勾选
│   严重等级 全部 · 并发 25 · 速率 150 …    │
│─────────────────────────────────────────│
│              [取消]  [创建计划]           │
└─────────────────────────────────────────┘
```

- **步骤 ①基本信息**：只有核心必填项 + 一个「高级选项」折叠（所属实例、启用状态）。
- **步骤 ②扫描参数（可选）**：整块可展开。默认收起，内容见 §5。
- 步骤条允许**直接点②**去看参数，也允许**忽略②直接创建**。

### 4.2 快通道（保护熟练用户）

这是本方案与"强制分步"的关键区别：

| 用户 | 路径 | 点击成本 |
|---|---|---|
| 新手 | ① 填 3 项 → 点「创建计划」 | 3 次输入 + 1 次点击 |
| 老手（要调参） | ① 填 3 项 → 点② → 调参 → 点「创建计划」 | 无额外往返 |
| 老手（不调参） | ① 填 3 项 → 点「创建计划」 | 与新手相同 |

**不做**：步骤 ② 的 `next` 校验关卡、必填标记、禁止跳过。任何一步都能直接提交。

### 4.3 与既有「一屏到底」决策的取舍（重要）

前置文档 §5.1 明确写过：「顶部保留步骤锚点条，点击滚动定位；**不做强制分步，一屏到底**，避免打断熟练用户。」

本方案**修改**该决策，理由与边界：

| | 旧决策 | 新方案 |
|---|---|---|
| 动机 | 尊重熟练用户，减少点击 | 新手在 30+ 控件前无法建立心智模型 |
| 做法 | 一屏到底 + 锚点 | 两步 + 步骤条 + **可跳过** |
| 熟练用户成本 | 0 | **0**（快通道，不做校验关卡） |
| 新手成本 | 高（被参数淹没） | 低（默认只面对 3 个必填） |

结论：**保留旧决策的内核（不打断熟练用户），用"可选步骤 + 快通道"替代"一屏到底"**。若评审认为风险偏高，可先只上"参数区默认收起"（§4 的最小版本），观察后再决定是否引入步骤条。

## 5. 任务 3：参数分层

### 5.1 三层结构

| 层 | 名称 | 默认态 | 内容 |
|---|---|---|---|
| L1 | **推荐视图** | 展开（在步骤②内） | 6 个高频项 |
| L2 | **高级设置** | 收起 | 其余 25 项，沿用现有 5 分组组织 |
| L3 | 进阶参数 | 收起（嵌套在 L2 内） | 现有 `advanced: true` 的 5 项 |

> 说明：L2 不把所有项都平铺成一个"高级"大折叠，而是**保留 5 分组**——用户想改代理时，按「网络与请求」找比在 25 项里翻要快得多。这是对"低频项收纳进折叠面板"的细化。

### 5.2 字段归属表（31 项逐项）

**L1 推荐视图（6 项）**——选取标准：① 直接改变"扫什么"的结果覆盖面；② 或直接决定"扫多久"，新手最需要感知。

| 字段 | 标签 | 理由 |
|---|---|---|
| `severity` | 严重等级 | 决定结果覆盖面，最常被业务方要求收紧 |
| `concurrency` | 并发数 | 直接决定速度/带宽，环境差异大 |
| `rateLimit` | 速率/秒 | 同上 |
| `timeout` | 超时/秒 | 目标网络慢时必须调 |
| `portScan` | 端口扫描 | 改变扫描范围，且是明显的时间成本 |
| `webFingerprint` | Web 指纹识别 | 同上，默认开启、常被关 |

**L2 高级设置（20 项，按原分组）**

| 分组 | 字段 |
|---|---|
| 性能与并发 | `smart`、`retries`、`maxHostError` |
| 节流与容错 | `throttle`、`reqLimitPerTarget`、`taskSmartTimeout`、`noFingerprint`、`breakpointOnVuln`、`monitorTargets` |
| 网络与请求 | `proxy`、`headers`、`sort`、`ports`、`skipHostDiscovery` |
| OOB 带外检测 | `oobAdapter`、`oobRateLimit`、`oobConcurrency` |
| PoC 与范围 | `pocSource`、`pocIds`、`search` |

**L3 进阶参数（5 项，维持现状）**：`bruteMaxRequests`、`maxRespBodySize`、`oobPollInterval`、`oobHitRetention`、`oobFinalizeTimeout`

### 5.3 效果对比

| 指标 | 优化前 | 优化后（默认态） | 变化 |
|---|---|---|---|
| 抽屉首屏可见参数控件 | 26 | **0**（收起成一行摘要） | 全部收起 |
| 展开参数区后可见 | 26 | **6**（推荐参数） | −77% |
| 抽屉首屏总控件（计划） | ≈ 32 | **≈ 7** | −78% |
| 参数区占创建流程比重 | 82% | **≈ 0%**（收起态）/ **≈ 37%**（展开态） | 核心信息成为主体 |
| 可访问参数总数 | 31 | 31 | 0 丢失 |

> 实施后「推荐参数」的实际渲染顺序：并发 → 速率 → 超时 → Web 指纹识别 → 端口扫描 → 严重等级（由字段表定义顺序决定，非 §5.2 表格的行序）。

### 5.4 可选的进一步简化（待定，需评审）

把「并发数 / 速率/秒 / 超时/秒」三件套合并为一个**扫描强度**三档预设（保守 / 标准 / 激进），一键映射到三组数值，保留"自定义"展开原值。

- 收益：L1 从 6 项降到 4 项，新手少面对 2 个陌生数值。
- 代价：新增一个概念与一层映射；与既有「扫描策略」的关系需要说清（策略是全局的，强度是这一次/这个项目的）。
- **建议**：本期不做，先用可观测数据（§7）验证 L1=6 项是否已够；若"并发/速率填错"仍是主要错误来源，下一期再引入。

## 7. 任务 4：用户测试方案与报告模板

> **执行边界**：本方案由人类研究员执行。AI 不能招募被试、不能观察真实用户，因此**本文不提供任何测试数据**；第 7.7 节只给模板与统计口径。

### 7.1 目标与假设

| 编号 | 假设 | 度量 |
|---|---|---|
| H1 | 分步 + 默认收起后，新手能在 **≤ 90 秒**内完成一次创建 | 中位完成时长 |
| H2 | 新手因"参数看不懂/以为必填"导致的中途放弃或报错显著下降 | 任务级报错率、放弃率 |
| H3 | "不知所措"的主观感受消失 | 满意度 ≥ 4.0/5，且"清楚下一步该做什么" ≥ 4.0/5 |
| H4 | 进阶用户仍能完成参数自定义，且耗时**不显著增加** | 进阶路径成功率 ≥ 90%，耗时增幅 ≤ 20% |

### 7.2 招募与被试

| 项 | 要求 |
|---|---|
| 样本量 | **≥ 20 人**，分两组各 ≥ 10：A 组「新手」（从未用过 afrog / 无同类工具经验）、B 组「进阶」（用过 afrog CLI 或其他漏扫工具） |
| 新手定义 | 未使用过 afrog，且过去 12 个月未独立配置过扫描器参数 |
| 排除条件 | 参与过本功能任何一轮设计评审或开发 |
| 招募渠道 | 内部非研发同事、外部安全初学者社群、客户方运维 |
| 设备 | 桌面浏览器 1440×900 起（与抽屉 512px 的可用空间一致）；每人独立会话 |
| 激励 | 与当地常规水平一致的小额报酬/礼品；不告知具体假设以免引导 |
| 伦理 | 签署知情同意；允许随时退出；录屏需单独授权；数据匿名化（编号 S01…） |

### 7.3 任务脚本（任务卡原文，直接给被试）

**任务 A（新手组必做）**
> 你的团队有一批外网资产（示例地址已提供）。请**新建一个项目**，把地址存进去，让同事下次能一键用同一套配置扫描。
> 完成后，请再**新建一个计划**，让它每天早上 9 点自动扫一次这批资产。

**任务 B（进阶组必做）**
> 同上创建项目与计划，另外满足：只扫 `high` 与 `critical` 等级；扫描走公司代理 `http://10.0.0.1:8080`；必须开启端口扫描并只扫 `80,443,8000-9000`。
> 完成后，请说明你会怎么再次修改这些参数。

**任务 C（两组都做）**：完成满意度问卷（7.6）。

观察记录点（研究员填写）：
1. 第一次点击的位置；2. 是否尝试阅读参数区；3. 是否表达"要填这么多？"；4. 是否找到"高级设置/进阶参数"；5. 报错次数与类型；6. 是否使用"使用推荐扫描参数"。

### 7.4 指标定义与采集

| 指标 | 定义 | 采集方式 |
|---|---|---|
| **完成时长** | 从抽屉打开到创建成功（第一次点击主按钮并成功）的墙钟时间；超 5 分钟记「未完成」 | 录屏时间轴 |
| **任务成功率** | 完成且满足任务卡全部约束的比例 | 研究员判定 |
| **操作报错率** | 触发的表单校验错误 / 后端错误次数 ÷ 被试数；按类型分：数值越界、必填缺失、格式错误 | 前端 toast + 录屏 |
| **放弃率** | 中途关闭抽屉或超时未完成 | 录屏 |
| **路径指标** | 是否展开「高级设置」；展开后是否成功返回主流程 | 埋点/录屏 |
| **满意度** | 5 分制李克特（7.6 问卷） | 问卷 |
| **可发现性** | "你如何修改上次没用到的参数？"回答正确率 | 任务 B 后访谈 |

### 7.5 判定阈值（Go / No-Go）

| 指标 | 通过线 |
|---|---|
| 新手任务成功率 | ≥ 90% |
| 新手中位完成时长 | ≤ 90 秒 |
| 新手平均报错次数 | ≤ 0.5 次/人 |
| 满意度 | ≥ 4.0 / 5.0 |
| "清楚下一步" | ≥ 4.0 / 5.0 |
| 进阶路径成功率 | ≥ 90%，且耗时增幅 ≤ 20%（对比优化前同一任务基线） |
| 参数自定义可达性 | ≥ 90% 能在 30 秒内找到目标参数入口 |

未达标项的处置：先做**定性根因归类**（认知/视觉/文案/交互），再决定是改文案还是改结构，**避免直接推翻分层**。

### 7.6 满意度问卷（原文）

5 分制（1=非常不同意，5=非常同意）：

1. 我很清楚这个页面要先填什么。
2. 我不确定的东西，可以直接不管它用推荐值。
3. 需要调整的参数，我能很快找到。
4. 整个创建过程没有让我困惑的地方。
5. 我愿意把这个功能推荐给同事。

另设两个开放题：① 最让你犹豫的一步是哪一步？② 哪个词你看不懂？
