# afrog Web 扫描体验与会员体系 PRD

## 1. 背景

`afrog -web` 启动后，浏览器访问 `ip:16868`，输入随机密码登录，可使用漏洞报告、PoCs、文档，以及**页面底部**的可视化漏洞扫描面板。

实际使用中，底部扫描功能使用率很低，用户体验差。定位到以下根因：

- **心智错位**：底部面板是"工具面板"心智，用户只会为完成任务而操作，不会主动去"用工具"。位置越深，越像附属功能。
- **参数优先而非任务优先**：`afrog -t url` 在 CLI 里是一条命令；底部面板却要求用户先理解任务、策略、资产集、PoC 选择四层概念。
- **主视图是日志流**：满屏 `PORT` / `WEBPROBE` / `HTTP` 行，用户看不出"还剩多少、发现了什么、下一步做什么"。
- **结果断链**：扫完不知道结果在哪，与漏洞报告页割裂。
- **没有回流理由**：CLI 更顺手，Web 未提供 CLI 给不了的能力（PoC 更新提醒、报告交付、差异对比、复现）。

结论：不是优化底部面板，而是**更换主入口与整体页面结构**。

现状代码锚点：

- 底部扫描面板：`afrogweb/src/lib/components/site-footer.svelte`（单文件约 108KB），仅在 `afrogweb/src/routes/(app)/+layout.svelte` 渲染一次；项目中**没有**独立的版权页脚。
- 扫描状态与事件流解析：`afrogweb/src/lib/stores/scan-store.svelte.ts`（逻辑完整，可直接复用）。
- 顶部导航：`afrogweb/src/lib/navigation.ts` 的 `mainNavItems`，仅 reports / pocs / docs 三项。
- 布局与主题基建：`afrogweb/src/app.css`（`container-wrapper` / `container` / `layout-fixed`）、`afrogweb/src/themes.css`（14 套主题变量）、`afrogweb/src/lib/user-config.svelte.ts`（layout 与 activeTheme，存 cookie `scn_user_config`）。
- 侧边栏组件：`afrogweb/src/lib/components/ui/sidebar/`（shadcn 组件已就绪）。
- 后端路由：`pkg/web/server_routes.go`，统一 JWT 鉴权，**当前无 role / 会员概念**。
- 会员能力：`pkg/curated/service/service.go`（`Login` / `Status` / `Update` / `Mount`），license 来自配置，启动时由 `cmd/afrog/main.go` 挂载，**尚未透出到 Web**。

## 2. 目标

### 2.1 产品目标

- 页面结构由上下结构改为**左右结构**，为后续功能增长提供可扩展的信息架构。
- 扫描功能从"参数配置台"重构为"**从目标到交付的流水线**"，成为用户愿意长期使用的主入口。
- 建立 Curated（知识星球会员）与普通用户的差异化体验，让会员价值可感知、可转化。
- 全部设计以**用户体验为中心**：判断标准是"用户要完成什么任务"，而不是"现有代码有什么功能"。

### 2.2 成功标准

- 新用户从登录到开始第一次扫描 ≤ 30 秒，操作步数 ≤ 3。
- 扫描过程中关闭页面，重新打开后能看到任务进度与已发现的命中。
- 扫描完成到导出报告 ≤ 2 次点击。
- 用户不再需要回到 CLI 完成一次常规漏扫。
- 会员与普通用户的界面差异在登录后 5 秒内可被感知。

## 3. 非目标

- 本阶段不重写扫描引擎，复用现有 `/api/scans` 与 SSE 事件流。
- 不引入 AI 辅助（置于 P2）。
- 不支持用户上传自定义背景图片（仅内置预设 + 纯色/渐变）。
- 不在本阶段实现团队协作与多租户。

## 4. 目标用户

### 4.1 普通用户（免费）

关注"能不能跑通一次有价值的扫描并看到结果"。免费版必须完整可用，不允许只给残缺体验。

### 4.2 Curated 用户（会员）

已通过知识星球获取 curated key 且未过期。关注"省时间、不漏、能交付"：PoC 时效性、周期扫描、报告交付、复测对比。

### 4.3 从 CLI 迁移的用户

熟悉 `afrog` 参数，关注迁移成本。Web 需提供与 CLI 等价的能力，并给出"等价命令"，使其无需重新学习。

## 5. 核心原则

1. **用户体验为中心**：所有功能与 UI 决策以用户任务为依据。
2. **目标是唯一必填项**：其余参数全部有默认值。
3. **用意图代替参数**：以"快速验证 / 标准漏扫 / 复测对比"三个预设作为入口，参数收进「高级」。
4. **过程不用盯**：任务后台执行，离开页面继续跑，回来即见进度与命中。
5. **结果即可交付**：报告导出、转台账、复现均为结果页的一级动作。
6. **结果优先于日志**：主视图是命中卡片，原始日志降级为「诊断」。
7. **付费墙克制**：免费版能出结果，会员卖"省时间 + 不漏 + 可交付"。
8. **会员能力后端校验**：不允许只靠前端隐藏。

## 6. 页面结构

### 6.1 整体布局

- 左侧：常驻菜单栏，icon + 功能名，宽度 240px，可折叠为 64px（图标 + tooltip）。
- 右侧：内容区，最大宽度限制并居中，**默认 1200px**。
- 宽版例外：扫描工作台、日志/终端、表格类信息密集页允许 1600px，按路由声明，不做全局开关。
- 底部：**完全移除**现有底部扫描面板，不保留底部常驻任务条；扫描状态改为左侧菜单的运行脉冲点与 badge。

### 6.2 左侧菜单

| 分组 | 菜单 | 普通用户 | Curated | badge |
| --- | --- | --- | --- | --- |
| 工作台 | 概览 | ✓ | ✓ | 进行中任务数 |
| 工作台 | 扫描 | ✓（受限） | ✓ 全量 | 运行脉冲点 + 命中数 |
| 工作台 | 项目 / 资产 | ✓（1 个） | ✓ 不限 | — |
| 结果 | 漏洞报告 | ✓ | ✓ | 今日新增 |
| 结果 | 漏洞台账 | 锁定（可进，看上锁预览） | ✓ | 待确认数 |
| 数据 | PoCs | ✓ | ✓ | 新增数 |
| 数据 | Curated 中心 | 锁定（预览） | ✓ | 新增 PoC 数 |
| 其他 | 文档 / 设置 | ✓ | ✓ | — |

锁定的菜单**可进入**，进入后为价值说明 + 上锁预览；不使用阻塞式弹窗。

### 6.3 背景与主题

内容区背景分三层：

1. 底色：沿用 `themes.css` 的 14 套主题变量。
2. 背景：内置预设 + 纯色/渐变。
3. 内容：卡片化（半透明 + `backdrop-blur`），保证任意背景下文字可读。

约束：

- 预设需按明暗主题各备一套。
- 日志/终端等密集页面强制关闭背景。
- 设置页提供「密集页面自动关闭背景」开关，默认开启。
- 正文对比度需满足 WCAG AA（≥ 4.5:1）。

## 7. 扫描体验

### 7.1 三层递进

**Layer 1 · Quick Scan（默认入口，覆盖多数场景）**

- 目标输入框：粘贴自动识别 URL / IP / CIDR / 域名，多行处理，自动去重、自动补 `http(s)`。
- 三个意图卡：快速验证（单目标·高危·约 30 秒）/ 标准漏扫（全量·可后台·约 2 分钟）/ 复测对比（与历史任务比对，会员）。
- 开始前展示预估：将使用的 PoC 数量与预计耗时。
- 「高级」折叠：并发、速率、超时、代理、OOB、端口扫描、PoC 范围、策略保存等全部原能力。

**Layer 2 · Task View（运行中）**

- 主视图为命中卡片流（severity 分色、目标、PoC 名、时间）。
- tab 固定为 `[漏洞] [资产发现] [统计] [诊断]`：
  - 漏洞：命中卡片。
  - 资产发现：端口、指纹、标题等（原 `PORT` / `WEBPROBE` 事件）。
  - 统计：severity 分布、扫描量、速率。
  - 诊断：原始日志（默认不展开），保留高亮与复制。
- 顶部：进度环、已完成/总数、命中计数、预计剩余时间、暂停/终止。
- 离开页面任务继续执行；左侧菜单显示运行脉冲点与命中数。

**Layer 3 · Result View（完成后）**

- 摘要：severity 汇总、耗时、目标数、PoC 扫描量。
- 清单：按 severity / 标签 / 目标筛选，支持搜索。
- 单条命中可展开：请求响应原文、`curl` 复现、单独重跑、转台账。
- 批量操作：全选后导出报告 / 转台账 / 标记误报。
- 扫描完成后自动落库为报告，无需手动保存。

### 7.2 意图预设

三个预设已确认足够，更多场景通过「高级」中的自定义策略满足。不引入首次使用向导。

### 7.3 与 CLI 的对齐

- 表单实时展示等价的 `afrog` 命令，可复制。
- 支持粘贴一条 `afrog` 命令，自动回填表单。

## 8. 会员体系

### 8.1 身份

- 后端 `GET /api/me` 返回 `role`（`curated` / `free`）与 `curated` 状态：是否有效、到期时间、剩余天数、PoC 数量。数据来自 `pkg/curated` 的 `Status()`。
- 密码登录（现有 JWT）保持不变，JWT claims 增加 `role`。
- 提供「激活会员」入口：在 Web 内粘贴 license，调用 curated `Login()` 并拉取 PoC，使 Web 本身成为激活渠道。
- 会员专属接口必须在后端做 role 校验。
- 未激活用户可见 curated PoC 的总量与新增动态，但内容锁定预览，以形成转化动机。

### 8.2 权益边界

| 能力 | 普通用户 | Curated |
| --- | --- | --- |
| 扫描 | 内置 PoC、单任务、并发受限 | 内置 + Curated 全量、多任务队列 |
| PoC 更新 | 手动 | 一键/自动更新 + 新增提醒 |
| 定时周期扫描 | ✗ | ✓ |
| 漏洞台账 | ✗ | ✓ |
| 扫描差异对比 | ✗ | ✓ |
| 报告导出 | Markdown | PDF / HTML / Excel + 品牌水印 |
| 通知集成 | ✗ | ✓（Webhook / 飞书 / 钉钉 / 企业微信 / Server 酱） |
| PoC 单独重跑 | ✗ | ✓ |
| 多实例编排 | 受限 | 不限 |
| AI 辅助 | 试用 | 不限（P2） |

### 8.3 会员能力细则

- **扫描差异对比**：自动匹配历史任务，输出 新增 / 已修复 / 仍未修复 / 无变化。
- **漏洞台账**：按项目聚合，状态流转（待确认 / 已确认 / 误报 / 已修复），支持备注与历史回溯。
- **报告导出**：模板（简版 / 标准 / 客户交付）+ 范围 + 内容勾选 + 品牌信息。
- **定时周期扫描**：以自然语言选择器呈现（每 X 的 Y 时间对 Z 项目跑 W 策略），底层生成 cron。
- **通知集成**：渠道配置 + 事件规则（任务完成 / 发现 high / 发现 critical / 失败）+ 发送测试。

## 9. 项目（资产空间）

一个项目 = 目标资产 + 默认策略 + 默认 PoC 组合 + 扫描历史 + 漏洞台账 + 定时任务 + 通知规则。

- 由现有资产库升级而来，不再是独立抽屉。
- 扫描结束后自动将目标存入项目，取消手动「保存为资产集」动作。
- 扫描工作台可直接选择项目，一键带入全部默认配置并复跑。

## 10. 现有底部能力的处置

| 现有能力 | 处置 | 说明 |
| --- | --- | --- |

## 11. 技术衔接

### 11.1 需新增或扩展的接口

- 身份：`GET /api/me`；JWT claims 增加 `role`；会员接口 role 校验中间件。
- 会员：`GET /api/curated/status`、`POST /api/curated/activate`、`POST /api/curated/update`。
- 项目：项目 CRUD 与关联（目标、默认策略、默认 PoC、历史）。
- 台账：状态流转与备注接口。
- 报告：导出接口（格式、模板、范围、品牌信息）。
- 定时任务：调度器与任务 CRUD（工作量最大，置于 P2）。
- 通知：渠道配置、事件规则、测试发送。

### 11.2 前端改造要点

- 新增 AppShell（左侧菜单 + 顶部窄条 + 右侧内容区），替换现有顶部横向导航。
- `navigation.ts` 改为分级 sidebar 配置（分组 / icon / href / badge / lock），按 role 过滤。
- 新增路由：`/`（概览）、`/scan`（扫描，含新建/进行中/历史）、`/scan/task/[id]`（结果）、`/projects`、`/ledger`、`/curated`。
- 复用 `scan-store.svelte.ts` 的事件解析逻辑，仅重构视图层；沿用现有 localStorage / IndexedDB 存储键以兼容历史数据。
- 删除底部面板渲染与 `site-footer.svelte`。

## 12. 实施阶段

### Phase P0：骨架与扫描重构

- 左右结构 AppShell、左侧菜单、1200px 内容区与宽版例外。
- 背景系统（内置预设 + 纯色/渐变 + 密集页自动关闭）。
- 移除底部面板，扫描 UI 迁入扫描工作台。
- 会员身份识别（`/api/me`）、会员徽章与锁定态。
- 扫描工作台：Quick Scan、Task View、Result View；等价 CLI 命令映射。

**发布顺序约束**：删除底部面板必须与扫描工作台同批次发布，否则用户将瞬间失去扫描入口。

### Phase P1：会员价值闭环

- 项目化（资产库升级为项目）。
- 漏洞台账、扫描差异对比。
- 报告导出（PDF / HTML / Excel）。
- Curated 中心（状态、更新、新增提醒）。
- 通知集成。

### Phase P2：进阶能力

- **已完成** 定时周期扫描（后端调度器）：频率预设（每 N 小时 / 每天 / 每周）+ 30s 调度循环 + 计划配置持久化到 `schedules.json`；任务元数据落库，重启后仍可查。
- **已完成** 多实例编排（v1 只读聚合 + 运行时增删节点）：`cluster` 配置登记同伴 + 30s 心跳（`/api/cluster/self`，集群共享 token）+ 「概览」页实例表（版本 / 状态 / 活跃任务 / CPU / 内存 / 延迟）；普通用户仅本机一行，Curated 展开全部。会员还可在概览页「编辑节点」直接增删同伴——保存后写回 `afrog-config.yaml` 并立即重建心跳，无需重启；手工改文件仍需重启。远程派发（跨节点起扫、任务归属与断连一致性）未做，属下一阶段。
- **已完成（v1）** AI 辅助：①**命中研判**（台账/任务详情点「研判」→ SSE 流式输出结论、判定依据、误报可能、人工验证、危害与影响、修复建议，证据为该条命中的原始请求响应）②**报告执行摘要**（报告页「AI 摘要」→ 执行摘要 / 整体风险评级 / 关键风险 / 处置建议，支持一键复制为 Markdown）。共性设计：只实现 OpenAI 兼容协议（用户自填 `ai.base_url/model/api_key`，设置页保存即生效）；只在点击时调用、结果按范围 + 模型缓存、重复查看不再请求、缓存命中不扣额度；发送前隐藏敏感头并截断超长内容（摘要只发统计与条目清单）；普通用户每月 20 次试用，Curated 不限次。**目标→扫描参数推荐**未开始。

## 13. 验收标准

- 新用户从登录到开始第一次扫描 ≤ 30 秒，操作步数 ≤ 3。
- 粘贴混合格式目标（URL / IP / CIDR / 域名）自动识别与去重正确。
- 扫描过程中关闭页面后重新打开，任务进度与已发现命中可恢复。
- 扫描默认视图为命中卡片；原始日志需主动切换至「诊断」才可见。
- 扫描完成到导出报告 ≤ 2 次点击。
- 内容区在 1920px 及以上宽度下不超过 1200px 且居中；宽版页不超过 1600px。
- 任意背景预设下正文对比度满足 WCAG AA（≥ 4.5:1）。
- 会员专属接口在后端拒绝非会员请求。
- 底部面板相关代码与渲染完全移除。

## 14. 风险与控制

### 14.1 布局大改导致老用户迷失

控制：保留现有 URL 路径可用（`/reports`、`/pocs`、`/docs`），登录后按 role 落到合适首页；提供折叠态菜单与 Cmd+K 快速跳转。

### 14.2 删除底部面板造成扫描入口真空

控制：严格执行"同批次发布"约束；扫描工作台未完成前不得移除底部面板。

### 14.3 背景与主题影响可读性与性能

控制：内容卡片化并设置半透明 + 模糊；密集页强制关闭背景；预设需按明暗两套验证；限制预设资源体积。

### 14.4 会员能力被前端绕过

控制：所有会员接口在后端基于 JWT `role` 校验，前端锁定态仅承担引导作用。

### 14.5 定时任务后端改造量超出预期

控制：置于 P2，先以通知与差异对比满足"回流理由"，避免阻塞主线。

### 14.6 复用扫描状态存储引发历史数据不兼容

控制：沿用现有存储键与数据结构，新增字段采用可选设计，避免破坏已有任务记录。
