## Web 控制台是什么

`afrog` 除了命令行，还内置了一个 Web 控制台。同一份引擎能力，换成图形界面来用：在浏览器里录目标、跑扫描、看进度、查结果、管资产与项目，并把命中沉淀成可跟踪的漏洞台账。

它解决的问题不是「多一种界面」，而是**把一次性的扫描变成可回溯的工作流**：

- 扫描在服务端持续运行，关掉浏览器不会中断
- 进度、资产发现、命中与诊断通过事件流实时推送
- 命中结果自动入库，按任务、按项目、按漏洞聚合
- 定时/计划扫描让「每天巡检一遍」不再依赖人工触发

## 启动与登录

启动 Web 控制台：

```bash
afrog -web
```

默认监听 `:16868`。要改地址，在 `afrog-config.yaml` 里配置：

```yaml
server: 127.0.0.1:16868
```

启动时终端会打印本次的访问密码：

```text
[INF] Web访问密码: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

密码在每次启动时随机生成，浏览器打开控制台后用当天这串密码登录。**关闭终端就等于关掉服务**，请把服务放到常驻环境运行。

> 注意：服务本身没有内置 HTTPS。要暴露到公网，请放在反向代理之后，并自行加上 TLS 与访问控制。

## 数据放在哪

| 内容 | 位置 |
| --- | --- |
| 扫描命中、资产、项目、漏洞台账、任务记录 | `~/.config/afrog/afrog.db`（SQLite） |
| 定时/计划扫描的配置 | `~/.config/afrog/schedules.json` |

命中结果是长期数据，会一直保留；任务记录（一次扫描的状态、目标、耗时、命中数量）只保留**最近 200 条**，用于界面上的历史列表。更早的任务仍可按任务 ID 在漏洞台账里查到它的命中结果。

## 界面导航

左侧导航按用途分组：

| 分组 | 页面 | 说明 |
| --- | --- | --- |
| 工作台 | 概览 | 数据总览与最近动态 |
| | 扫描 | 发起扫描、查看进行中与历史任务 |
| | 计划扫描 | 定时/周期性重跑同一份扫描配置 |
| | 项目 | 一组资产 + 其扫描历史的组织单位 |
| | 资产 | 扫过的目标自动沉淀，可打标签、收藏 |
| 结果 | 漏洞报告 | 按任务/关键字/级别筛选命中记录 |
| | 漏洞台账 | 命中的状态流转（待确认/已确认/误报/已修复）与备注 |
| 数据 | 漏洞库 | 浏览内置/精选 PoC 与漏洞详情（名称、详情、参考、影响版本、修复建议），编写自己的 PoC |
| | 会员中心 | 会员配置与激活、精选 PoC 的挂载状态与更新 |
| 其他 | 设置 | 账号、通知、服务信息 |

标记为会员能力的页面（计划扫描、漏洞台账、Curated）普通用户仍可进入，但页面内为上锁预览，升级后即解锁。

## 发起一次扫描

在「扫描」页输入目标即可开始。目标框会自动识别并归一化下面这些形态，一行一个或逗号分隔都可以：

- URL：`https://example.com/login`
- 域名：`example.com`
- IP 与带端口：`192.168.1.10:8080`
- CIDR：`10.0.0.0/24`

扫描意图决定跑多少 PoC：

| 意图 | 适用场景 |
| --- | --- |
| 快速验证 | 单目标、高危 PoC、几十秒出结论 |
| 标准漏扫 | 全量 PoC、可后台运行、覆盖面优先 |
| 复测对比 | 与该项目上一次扫描自动比对，看修没修（会员） |

需要更细的控制时展开「高级」：并发、速率、超时、代理、OOB、端口扫描、Web 探测、PoC 范围、漏洞级别过滤等参数与命令行完全一致。

「复测对比」需要任务有归属项目：项目是找到「上一次扫描」的依据，从项目发起扫描才能做对比。

## 任务列表与实时过程

「扫描」页把任务分成两段：

- **进行中**：正在跑或排队的任务，按并发上限排队执行
- **历史任务**：已完成 / 已失败 / 已终止的任务

进行中的任务可以**暂停、继续、终止**。暂停与继续作用在扫描进程上，计时会同步冻结。

点开一条任务，过程通过事件流实时推送：

| 页签 | 内容 |
| --- | --- |
| 漏洞 | 命中的漏洞清单，可展开看请求/响应证据 |
| 资产发现 | 端口扫描与 Web 探测的结果（启用 `-w` 或端口扫描时才有） |
| 与上次对比 | 与同一项目上一次扫描的差异：新增 / 已修复 / 仍未修复（会员） |
| 统计 | 各级别命中数量、目标数、PoC 数、实际执行数 |
| 诊断 | 引擎的过程日志，用于排查「为什么没跑」 |

扫描结束后可以把整份任务结果导出为 HTML / Excel / Markdown，或打印成 PDF（导出为会员能力）。

**任务来自哪里都可以看**：计划扫描触发的任务不是在这个页面发起的，但同样会出现在列表里并带「计划」来源标记；打开时会把开扫以来的过程事件补发一次，所以 Web 探测、端口、命中都不会缺。

**服务重启后**：任务记录存在本地数据库里，重启后仍能在历史列表中打开最近的任务，只是逐条事件明细不再保留——命中结果本身在漏洞台账里始终可查。

## 多实例（概览页）

「概览」页的「多实例」卡片汇总本机与同伴 `afrog` 实例的运行状态：版本、在线状态、活跃任务数、CPU / 内存，以及心跳延迟。

- 单实例（未配置 `cluster`）时只有本机一行，卡片里同时给出配置示例
- 同伴在 `afrog-config.yaml` 的 `cluster.peers` 中登记，同一集群共用 `cluster.token`，见[配置文件说明](./05-configuration.md)
- 本实例每 30 秒读取一次同伴状态；同伴不可达时如实显示原因（令牌不匹配 / 版本过旧 / 无法连接），而不是让节点从列表里消失
- 聚合视图是 Curated 会员能力：普通用户能看到「集群里共有几个节点」，但只展开本机一行

**运行时增删节点（会员，无需重启）**：卡片右上角的「编辑节点」可以直接改本节点名称、集群令牌和同伴列表，保存后写回 `afrog-config.yaml` 并立即重建心跳——新增的节点马上进入列表（首次探测期间显示「探测中」），不需要重启 `afrog`。

间隔 30 秒的心跳是固定节奏，服务启动时读一次配置、之后不再重新读文件；所以如果是手工改的 `afrog-config.yaml`，仍需重启才生效。保存时的校验规则：地址只支持 http/https（可省略协议前缀）、重复地址自动去重、同伴最多 64 个、配置了同伴就必须填集群令牌。

### 跨节点派发（会员）

「扫描」工作台多了一个「执行节点」选择器（列出在线同伴，默认本机）。选中某个节点后点「开始扫描」，这次扫描就由该节点执行。

- **任务归属执行节点**：任务、事件流与命中明细都留在执行节点上（单一数据源），发起端只保存一条镜像记录，显示节点名、状态、进度与命中数
- **命中只读代理**：在发起端打开远程任务即可只读查看该节点上的命中明细，不需要单独登录那个节点
- **命中回填（任务终结后）**：远程任务一到终态，发起端就把它的命中回填进本机结果库——报告、台账与导出都能查到，条目上标出来源节点（报告页列表、台账列表，以及 HTML / Excel / Markdown 三种导出产物）。回填是幂等的：先按该任务清空再整批写入，重试不会写出重复条目，请求响应原文也一并保留（AI 研判同样可用）
- **断连一致性**：派发带幂等键，网络抖动或重试不会重复起扫；联系不上执行节点时任务标为「节点失联」，保留最后一次对账到的状态（不误判为失败），恢复后自动继续对账
- **重启不丢**：镜像记录落盘到 `~/.config/afrog/remote_tasks.json`，发起端进程重启后任务列表照常显示，未完成的任务自动恢复对账（任务本身始终在执行节点上运行）
- **按项目派发**：在发起端选中项目即可派发。发起端会在本地把项目解析成具体目标清单后再下发，执行节点无需拥有该项目、也不会有这次任务的任何归属；发起端回填命中时会登记到来源项目名下，所以项目的台账筛选与项目报告里同样能看到这些远程命中
- **计划扫描也能派发**：计划表单同样可选「执行节点」，到点自动把这次扫描交给该节点执行（见 [定时与计划扫描](./09-scheduled-scans.md)）
- **前提**：两端配置同一个 `cluster.token`（未配置令牌的实例不接收派发），且只有 Curated 会员可以派发

## 资产、项目与漏洞台账

这三个页面构成扫描之外的工作面：

- **资产**：任何一次扫描的目标都会自动沉淀为资产（零维护），也可以手工新增/导入。扫描过的资产会记录 `last_scan_at` 与 `last_task_id`，方便回头看「这个目标上次什么时候扫过」。选中一批资产可以直接带到扫描页开扫。
- **项目**：把一组资产组织成一个业务单位，项目是扫描历史归属、复测对比、按项目统计的依据。
- **漏洞台账**：把命中按「PoC + 目标」聚合成一条待办，跟踪状态（待确认 / 已确认 / 误报 / 已修复）与备注。计划扫描的「查看上次结果」就是跳到按任务筛选的台账视图。

## AI 研判

台账每一行、以及任务详情「漏洞」页签里的每条命中，都有一个「研判」按钮。点开后会逐字流式输出六段内容：

- **结论**：是不是真实漏洞，附置信度（高/中/低）
- **判定依据**：逐条对应证据，指明是哪一段请求或响应支撑结论
- **误报可能**：具体的误报场景（例如「仅回显了 payload，未体现执行结果」）
- **人工验证**：3 步以内可照做的确认动作
- **危害与影响**、**修复建议**

它解决的是「扫出一堆结果，不知道哪条是真的、先看哪条」：把逐条人工读请求响应的几分钟，压到读一段结论的几十秒。

几点设计上的约束，用之前值得知道：

- **不是自动跑**：只在你点击时调用一次，不会后台批量消耗；同一条命中重复查看走本地缓存，不再重复请求
- **只依据证据推断**：提示词要求「不得引入证据里没有的事实、证据不足必须直说、严禁编造 CVE 与厂商公告」，输出的只是建议
- **不替你下结论**：台账状态仍由你手动改，AI 输出不会自动写成「已确认」
- **发送前脱敏**：`Cookie`、`Authorization`、`Set-Cookie` 等敏感头会被隐藏，超长请求/响应会截断；但这条命中的请求与响应仍会发给你配置的模型服务
- **未配置不迷路**：还没接入模型时按钮依然可见，点开直接引导到「设置 → AI 辅助」；免费试用每月 20 次，Curated 会员不限次

接入方式见[配置文件说明](./05-configuration.md)的 `ai` 字段字典，或直接在「设置 → AI 辅助」里填写（保存即生效，无需重启）。

### 报告执行摘要

「报告」页右上角还有一个「AI 摘要」按钮，用来生成一份**能直接贴进交付报告**的执行摘要：

- 带「本次扫描」时（例如从任务详情或计划扫描的「查看上次结果」进来），摘要针对这次扫描：扫了什么范围、整体风险评级、关键风险、处置建议
- 没带任务时按当前筛选（严重级别 / 关键字）跨任务汇总，摘要里会明确写成「当前筛选结果」而不是「本次扫描」，避免把范围说错
- 输出可一键「复制」成 Markdown，粘到自己的报告里即可；同样的范围重复打开走缓存，不会重复调用

摘要只把**统计与条目清单**发给模型（不发送原始请求响应），所以它擅长讲全局和轻重缓急；需要判断某一条命中是不是真的存在，用上面的「研判」。

### 扫描参数推荐

在「扫描」工作台粘贴目标后，点「AI 推荐参数」，AI 会结合目标的规模、类型（URL / IP / CIDR / 域名）与当前意图（快速验证 / 标准漏扫），给出 2~4 条推荐理由，并把并发、速率、超时、智能并发、端口扫描、Web 指纹、严重级别等参数整理成一份可直接采用的配置。抽屉底部点「应用推荐参数」即写回表单（之后仍可手动微调），不满意可「重新生成」。

- **只上传目标画像**：发送的是目标数量、类型分布与最多 20 条样例，不是完整目标清单
- **参数有边界**：越界数值会被夹回表单允许的范围，非法的严重级别会被丢弃，不会把表单填成不可用状态
- **只覆盖推荐项**：模型没给出的字段保持你当前的设置，不会顺手覆盖其他参数
- **同一批目标重复打开走缓存**，不会重复调用；未配置模型时会引导到「设置 → AI 辅助」

## 会员中心（Curated）

「会员中心」页把 `afrog-config.yaml` 的 **`curated` 段**做成了可视化表单：会员能力开关、服务地址、更新渠道、License、自动更新与挂载超时。改完点「保存并应用」即写回该文件。

- **保存即生效，无需重启**：保存会按新配置重新装配会员能力，并顺带登录、拉取一次 PoC，因此这一步就等价于「激活」——填好服务地址与 License 后直接保存即可（拉取可能需要几十秒）
- **拉取失败不等于激活失败**：配置已经写回并生效，失败原因会同时出现在提示与「会员」状态卡里，可稍后点「检查 PoC 更新」重试
- **服务地址留空即视为不使用会员能力**；会员开关的 `auto` 与 `on` 行为一致
- 未激活时页面还给出上锁预览与知识星球入口：购买与 License 发放都在站外完成，站内不做支付
- 会员状态卡显示剩余天数、到期时间、会员 PoC 数量、最近更新与清单版本；到期时间取自 license 的真实到期日（服务端 `licenses.expires_at`），不限期显示「不限期」，服务端未提供该信息时显示「—」
- 注意：保存会**整段重写** `curated` 段，因此该段内原有的注释会被覆盖（同文件其它段落不受影响）

## 与命令行的关系

Web 控制台不是命令行的替代品，两者共用同一套引擎与 PoC：

- 命令行适合一次性、脚本化、需要自定义输出的场景
- Web 控制台适合持续运行、需要看过程与留痕、需要多人查看结果的场景

扫描参数（并发、速率、超时、OOB、端口扫描、Web 探测、PoC 范围）在两边的口径完全一致，见 [CLI 参数总览](./04-cli-options.md)。
