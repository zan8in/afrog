## 为什么需要它

漏扫的价值不在「扫过一次」，而在**持续地扫**。计划扫描把一次配置变成周期性任务：同样的目标、同样的 PoC 范围、同样的参数，按固定节奏自动重跑，你只需要在结果有变化时出手。

典型用法：

- 每日巡检：核心资产的完整漏扫，每天固定时间跑一次
- 每周复测：上线周期长的系统，每周一早上确认上周的修复没有回归
- 每小时盯梢：新暴露面或高危 PoC 范围，缩短暴露窗口

计划扫描是 **Curated 会员能力**：普通用户可以看到入口，但页面为上锁预览。

## 创建一条计划

在「计划扫描」页新建，需要填四件事：

| 项目 | 说明 |
| --- | --- |
| 计划名称 | 出现在任务列表里，建议写清业务含义，例如「客户A每日巡检」 |
| 目标 | 选一个**项目**（推荐，资产增删自动跟随），或直接填一组临时目标 |
| 扫描配置 | 与手动扫描完全一致：意图、PoC 范围、并发/速率/超时、端口扫描、Web 探测（`-w`）、OOB 等 |
| 执行频率 | 见下表 |
| 执行节点 | 可选：让某个在线同伴执行本次扫描（见下）；留空即本机执行 |

### 频率预设

不引入 cron 表达式，用三个预设覆盖绝大多数巡检需求：

| 频率 | 参数 | 例子 |
| --- | --- | --- |
| 每 N 小时 | N（1–168） | 每 6 小时 |
| 每天 | HH:MM | 每天 09:30 |
| 每周 | 星期几 + HH:MM | 每周一 08:00 |

保存时会立刻校验目标：项目不存在、项目下没有有效资产、或临时目标为空，都会直接报错——宁可现在告诉你，也不要留下一条每到点就静默失败的计划。

单实例最多 100 条计划。

### 让其他节点执行（会员）

计划不一定要在本机跑：在表单里选一个「执行节点」，到点后这次扫描就会被派发给该同伴执行。

- 只有**在线**同伴会出现在选择器里；保存时还会校验节点仍在集群配置中、且本实例已配置 `cluster.token`，配置错误在保存时就报出来，不留到点静默失败
- **项目目标在派发前于本机解析**成具体目标再下发，执行节点不需要拥有这个项目
- 任务与命中都留在执行节点（单一数据源），发起端只保存一条镜像记录：任务列表里标为远程来源、显示节点名并带计划 ID，可只读查看命中明细
- 任务终结后发起端会把命中**回填**进本机结果库：报告、台账与导出都能查到，报告与台账列表的条目上标出来源节点；回填幂等（先清后写），节点长期不可达会持续重试，界面上的「节点失联」即为此状态
- 节点连不上时任务标记「节点失联」并保留最后一次对账到的状态（不误判为失败），恢复后自动继续对账；重试不会重复起扫（派发带幂等键）

## 什么时候真正开始扫描

**保存（新建或编辑）不会立即执行**，只是排入队列并算出下一次执行时间。到点由服务端的调度器触发：

- 调度器每 30 秒检查一次计划表，到点的计划立即起跑
- 想要马上验证配置，用列表里的**「立即执行」**：它只跑这一次，不影响原有的续排节奏
- 每次触发的任务与手动扫描走同一条路径：同样沉淀资产、记入项目、走通知，结果同样进台账（配了执行节点的计划除外，其任务与命中留在执行节点，见上）

计划列表里每条会显示频率、目标来源、最近一次执行的结果与下一次时间：

```text
客户A每日巡检
每天 16:01
项目：客户A · 目标 42 个 · 上次：已触发 2026-09-30 16:01 · 下次：2026-10-01 16:01
```

`上次` 有四种状态：

| 状态 | 含义 |
| --- | --- |
| 尚未执行 | 计划建好但还没到过点 |
| 已触发 | 已按计划起跑，结果到扫描页/台账看 |
| 触发失败 | 到点了但没能起跑（例如目标已失效），会给出原因 |
| 已跳过 | 未执行（例如会员到期） |

### 改频率、停用与删除

- **改频率**：保存后按新频率重新计算下次时间
- **停用**：不再触发；**重新启用**时以当前时间为基准续排，不会补跑停用期间错过的次数
- **删除**：计划立即消失，已经跑出来的任务与结果不受影响

## 停机期间错过的计划

服务启动时会立刻检查一次计划表：只要「下次执行时间」已经过去，就**补跑一次**，随后按原频率继续排期。

也就是说，服务停了三天再启动，不会把三天的量一次性轰出来——每个计划只补一次，把最新一轮的结果拿回来。

## 结果去哪看

计划触发的任务不会只活在后台，处处可查：

- **扫描页**：任务出现在列表里并标注「计划」来源，名称默认取计划名；过程事件（Web 探测、端口、命中）可补看，详情页同样可看统计与诊断
- **列表里的「查看上次结果」**：跳转到按该任务筛选的漏洞台账，看这次到底命中了什么
- **漏洞台账 / 漏洞报告**：按项目、按时间、按级别聚合，跟踪状态流转
- **通知**：命中与收尾消息按计划配置的通道推送

服务重启后，最近的任务记录仍在扫描页可见（任务记录保留最近 200 条），命中结果始终可在台账按任务 ID 查到。

## 会员到期会怎样

计划不会静默消失：

- 到点仍会推进时间，但不再起跑
- 该次执行记为 `skipped`，原因写明「定时扫描为 Curated 会员专属」
- 续费后无需重建计划，下一次到点即恢复执行

## 配置放在哪

计划配置保存在 `~/.config/afrog/schedules.json`，与数据库（`~/.config/afrog/afrog.db`）分开：

- 计划是配置，可备份、可手工审阅
- 任务是数据，命中结果长期保留
