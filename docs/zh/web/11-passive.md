## 这是什么

主动扫描需要你提供目标清单；被动扫描反过来——**让业务流量经过 afrog，它从真实请求里找漏洞**。

打开开关后，afrog 在本机起一个 MITM 代理。浏览器或 App 把流量指到它上面，它解密、观察、必要时重放少量请求，命中与结论都写入与主动扫描相同的库：

- 命中进入「漏洞报告」与「漏洞台账」，可以和主动扫描的结果一起筛选、研判、导出
- 扫描过的目标自动沉淀为资产，项目归属与主动扫描共用同一套口径
- 所有「测没测、没测为什么」都记入覆盖度台账

一句话：**主动扫描回答「这个目标有没有洞」，被动扫描回答「真实在用的接口有没有洞」。**

## 启动与证书

在「被动扫描」页点「开始」，或在 `afrog-config.yaml` 里打开 `passive.auto_start`。默认监听 `127.0.0.1:16869`。

HTTPS 需要信任 afrog 的根证书：在页面上「下载 CA 证书」并导入系统的受信任根证书列表。不装证书时只能看到 HTTP 流量，HTTPS 会因证书校验失败而无法解密。

> 只监听回环地址是有意为之：被动代理掌握的是解密后的全部流量，暴露到公网等于把这个能力开放给他人。确实需要手机接入时再改成 `0.0.0.0`，并用防火墙限制来源。

## 配置

```yaml
passive:
  auto_start: false          # afrog web 启动时自动开启
  host: 127.0.0.1            # 监听地址
  port: 16869                # 监听端口
  upstream: ""               # 上游代理，如 http://127.0.0.1:8080；空表示直连
  detectors: [sqli, extract] # 启用的检测器
  max_rps: 100               # 重放请求的全局速率上限
  host_concurrency: 4        # 单目标并发上限
  detect_workers: 4          # 检测池并发（真正的检测吞吐旋钮）
  queue_size: 4096           # 门控入口队列容量，满即丢弃、不回压业务流量
  project_id: ""             # 命中的归属项目；空表示未归属
  scope_host_allow: []       # 只扫描这些 Host（支持通配后缀）
  scope_host_deny: []        # 永不扫描这些 Host（优先于 allow）
  scope_path_deny: []        # 永不扫描这些路径，如 /logout、/pay
  scan_unsafe_methods: false # 是否检测 PUT/PATCH/DELETE 等非幂等请求
```

可在页面上直接改并保存，写回同一个配置文件、立即生效。

检测器一览：

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `sqli` | 网络类 | 参数注入检测，会重放请求 |
| `misconfig` | 本地类 | Cookie / 响应头等安全配置问题，零流量 |
| `exposure` | 网络类 | 每 origin 一轮敏感文件探针（`.git`、`.env`、备份包等），有独立预算 |
| `extract` | 本地类 | 敏感信息提取（HAE 等价能力），产物独立于漏洞台账 |
| `fingerprint` | 本地类 | 技术栈与组件识别 |
| `recon` | 本地类 | 从流量里补充路径、参数等侦察信息 |

## 两阶段流水线

每条事务先过**门控池**，再决定要不要进**检测池**：

1. **门控（零流量）**：跑本地类检测器（配置检查、提取、指纹），并判断网络类检测器是否值得重放。静态资源、范围外主机、已确认的注入点都会在这里被短路。
2. **检测（会重放）**：只有确认需要检测的事务才进入，按 `detect_workers` 并发执行。注入检测会对同一请求做多次变形重放。

因此「捕获数」涨得快、检测数涨得慢是正常的：大量请求在门控阶段就被判定为不值得检测。

`scan_unsafe_methods` 默认关闭：检测器会重放同一请求数十次，对 `PUT/PATCH/DELETE` 重放有真实的业务破坏风险。

## 页面页签

| 页签 | 看什么 |
| --- | --- |
| 命中 | 被动发现的漏洞，按项目/检测器/关键字筛选；可单条提升进台账 |
| 信息提取 | 从响应中提取的手机号、邮箱、密钥、内网地址等产物 |
| 覆盖度 | 按「资产 × 检测器」展示测没测、没测为什么 |
| 实时流量 | 最近若干条事务的处置结果与原因（仅内存，不落库） |
| 在途检测 | 当前正在检测的事务，用于解释「捕获在涨、检测不动」 |
| 诊断 | 代理、解析、存储各环节的错误与计数 |

## 覆盖度

覆盖度回答的不是「发现了什么」，而是「还有哪里没看」。

聚合口径是 **authority（`host[:port]`，小写，不区分 http/https）**，每个 `(项目, 资产, 检测器)` 一行，状态取历次结论里最强的一次：

| 状态 | 含义 | 优先级 |
| --- | --- | --- |
| `hit` | 该检测器在这个资产上检出过 | 最高 |
| `tested` | 真正执行过，没有确定结论 | 次之 |
| `error` | 执行过程中出错 | 再次 |
| `skipped` | 没执行，附具体原因（静态资源、范围外、参数不足、队列满等） | 最低 |

两条不变量：

- **只升不降**：一次跳过永远不能把「已测过」擦成「没测过」，否则使用者会重复补扫。
- **计数独立累加**：`samples`、`hits`、`skipped`、`errors` 各算各的，不会被状态覆盖。

页面下方还会列出「未覆盖资产」：资产库里有记录，但没出现在被动流量里。不可执行地址（例如把端口误存成主机的 `21`）会在这类清单中被过滤掉。

## 证据血缘

打开一条被动命中的详情，除了请求/响应证据，还能看到它「从哪来、靠什么判定」：

- **资产锚点**：这条命中挂在哪个资产上，可直接跳到资产页
- **判定手法**：检测器、漏洞类型、注入位置、技术/方言/绕过/构造方式
- **追踪步数**：这次判定经过了几步重放
- **同资产覆盖度**：同一资产上各检测器的结论快照，用来判断「是只有这一个检测器看过，还是全看过了」

血缘是落库字段的直接展示，不做推测：`asset_id` 在命中写入时解析，解析不到时按 host 重算。

## 资产关系

在「资产」页选中一个资产，点「关系」按钮，会展开以它为根的父子图：

| 方向 | 说明 |
| --- | --- |
| 下游穿透 | 从粗到细：网段 → IP → 主机端口 → URL |
| 上游归属 | 反过来看某个 URL 属于哪个 IP/网段 |

推导规则全部是程序化的，不做 DNS 解析，只做三层：

- `authority`（host[:port]） → `url`
- `ip` / `domain` → `hostport`
- IPv4 `/24` → `ip`

IPv6 网段与 eTLD 主域**不推导**：前者会让图爆炸，后者需要完整的公共后缀列表，宁可少一条边也不猜。

图里只存边、不存节点。资产表里没有的中间节点（例如从未单独入库的 authority）会在展示时按需合成，并标记为「自动推导」，不会污染资产数量与统计口径。

## 下一步建议

概览页的「下一步建议」卡片由确定性规则从既有数据推导，不调用模型，每条都能直接落到一个动作：

| 规则 | 判据 | 动作 |
| --- | --- | --- |
| 未扫描资产 | 没有扫描轨迹，也没被被动覆盖 | 一键带目标去扫描页 |
| 覆盖空洞 | 有被动流量，但所有检测器都只有 `skipped` | 跳到覆盖度明细 |
| 陈旧资产 | 超过 30 天未复测 | 一键带目标去扫描页 |
| 未入台账命中 | 被动命中已过零误报门控，但 `promoted = 0` | 跳到被动命中页 |

「未扫描资产」与「陈旧资产」严格互斥：前者要求从未扫过，后者只取扫过的资产，避免同一个目标被两条建议重复点名。

每条建议右侧的 × 表示「7 天内不再提示」：忽略记录只存在当前浏览器（localStorage），不影响其他设备；卡片右上角的「已忽略 N · 恢复」可以一键恢复，7 天后也会自动重新提示。

建议里的目标会先过滤可执行性：像 `21` 这种把端口误存成主机的地址不会出现在「一键扫描」里。启动时还会清理一批历史脏资产——只删「从未扫描、未收藏、未打标签、未归档」的行，其余保留。

## 安全闸门

被动扫描会主动发包（`exposure` 探针、注入重放），因此高危动作统一受 `security` 段约束：

```yaml
security:
  actions:
    cluster-dispatch: allow   # 集群远程派发
    exposure-probe: allow     # 被动敏感路径探测
  allow_targets:              # 目标白名单；非空即硬边界
    - corp.example            # 精确 host，不含子域
    - "*.corp.example"        # 通配后缀，含自身
    - 10.0.0.0/24             # CIDR
```

语义：

- **默认全部 allow**：升级不改变既有行为。
- **mode**：`allow` 放行；`deny` 拒绝；`ask` 需要人工确认——服务端无人值守，因此等价于「拒绝并记录」，绝不静默放行。
- **白名单是硬边界**：一旦配置，白名单外的目标一律拒绝，与 mode 无关。这防的是「集群密钥泄露后本机被当成跳板」。
- **精确 host 不覆盖子域**：要覆盖子域请写 `*.example.com`。

生效范围：

- `cluster-dispatch`：接收远程派发前校验目标。被拒的派发不占用 `dispatch_id`，补上白名单后可以重试。
- `exposure-probe`：在门控阶段按 origin 裁决一次；被拒则不发起任何探针，覆盖度记 `skipped` 并带上拒绝原因。裁决结果按 origin 缓存，不会逐请求刷审计。

概览页的「闸门详情」抽屉只读展示当前动作配置、白名单与最近裁决。裁决会追加写入 `~/.config/afrog/guard_audit.jsonl`，因此重启后仍能看到之前的拒绝与放行记录；界面展示最近 200 条，文件超过 1MB 时只保留最近 1000 条。改策略请改配置文件——避免「点一下就把自己的扫描边界关了」。

## 常见问题

**看不到任何流量？**
先确认浏览器/设备的代理指向 `127.0.0.1:16869`；HTTPS 站点还要确认根证书已导入受信任列表。再看「诊断」页有没有代理层错误。

**捕获在涨，但检测不动？**
看「在途检测」与「实时流量」：多半是门控判定不值得检测（静态资源、范围外、注入点已有结论），或检测池/队列已满。`dropped-detect` 表示已确认需要检测但检测能力饱和，存在漏报风险。

**覆盖度里全是 skipped？**
看原因列：常见是接口没有参数、响应体过小、目标落在扫描范围之外，或被安全闸门拒绝。

**被动命中和主动扫描结果重复吗？**
同一个库、同一套台账。去重按 `(项目, 指纹)` 聚合，反复命中的同一条只累加次数。
