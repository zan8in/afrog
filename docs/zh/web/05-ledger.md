## 台账解决什么问题

扫描会产出一堆命中，但「哪条是真的、先看哪条、修没修」才是真正要跟踪的事。**漏洞台账**把命中按「PoC + 目标」聚合成一条**待办**，让结果从「一次性列表」变成「可流转的清单」。

> 台账是会员能力。普通用户可进入页面看到上锁预览，升级后解锁。

## 状态流转

每条台账记录有状态与备注：

| 状态 | 含义 |
| --- | --- |
| 待确认 | 新命中，尚未人工判断 |
| 已确认 | 人工确认是真实漏洞 |
| 误报 | 判定为误报 |
| 已修复 | 已确认修复 |

状态由你**手动流转**，可以补充备注记录处置过程。AI 输出不会自动改状态。

## 筛选与来源

台账支持按**任务、项目、关键字**等维度筛选：

- 从某次任务的详情进来，会带上该任务的筛选；
- 计划扫描的「查看上次结果」就是跳到按任务筛选的台账视图；
- 远程派发的命中回填后，条目上会标出来源节点。

## AI 研判

台账每一行都有一个「研判」按钮，点开后会逐字流式输出结论、判定依据、误报可能、人工验证步骤、危害与修复建议——把「逐条读请求响应」的几分钟压到「读一段结论」的几十秒。

- 只在点击时调用一次，同一条命中重复查看走本地缓存；
- 发送前对 `Cookie` / `Authorization` 等敏感头脱敏；
- 未配置模型时按钮仍可见，点开引导到「设置 → AI 辅助」。

详见 [AI 辅助](./09-ai.md)。

## 与复扫的关系

台账是「跟踪到修复」的闭环末端：确认修复后，可以再发起一次扫描（或按项目做[复测对比](./03-tasks.md)）来验证。
