## 任务列表

「扫描」页把任务分成两段：

- **进行中**：正在跑或排队的任务，按并发上限排队执行
- **历史任务**：已完成 / 已失败 / 已终止的任务

进行中的任务可以**暂停、继续、终止**。暂停与继续作用在扫描进程上，计时会同步冻结。

任务的来源会有标记：页面手动发起的、[计划扫描](./07-scheduled-scans.md)触发的（带「计划」来源）、以及其他控制台[远程派发](./08-cluster.md)过来的任务。

## 任务详情与实时事件流

点开一条任务，过程通过**事件流**实时推送，分为几个页签：

| 页签 | 内容 |
| --- | --- |
| 漏洞 | 命中的漏洞清单，可展开看请求/响应证据 |
| 资产发现 | 端口扫描与 Web 探测的结果（启用相关选项时才有） |
| 与上次对比 | 与同一项目上一次扫描的差异：新增 / 已修复 / 仍未修复（会员） |
| 统计 | 各级别命中数量、目标数、PoC 数、实际执行数 |
| 诊断 | 引擎的过程日志，用于排查「为什么没跑」 |

### 事件流的两点保证

- **断线续传**：事件带序号，浏览器重连时会带上 `Last-Event-ID` 从断点继续，不漏事件。
- **补发**：非本页发起的任务（如计划扫描）打开时会把开扫以来的过程事件补发一次，所以 Web 探测、端口、命中都不会缺。

## 导出与打印

扫描结束后可以把整份任务结果导出为 HTML / Excel / Markdown，或打印成 PDF（导出为会员能力）。导出内容与[漏洞报告](../user-guide/06-output-and-report.md)口径一致。

## 服务重启之后

任务记录存在本地数据库里，重启后仍能在历史列表中打开最近的任务；只是**逐条事件明细不再保留**——命中结果本身在[漏洞台账](./05-ledger.md)里始终可查。
